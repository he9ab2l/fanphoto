# FanPhoto 全新开发计划

制定于 2026-09-07，依据 `../重构要求.md` 与用户最新指令。

## 范围修订

用户明确要求：**不是兼容旧项目的迁移；按全新项目开发，新的设计、新的架构，
公开展示页和管理页都重做；以前的代码、数据与测试站可以清理。**
因此不保留旧 API、旧表结构、旧路由、旧 UI 或兼容适配器。
本地资源审查和新下载的真实风景原片继续使用。

## 已完成的开工审查

- 原项目在 `fanphoto/`，开工时 Git 工作区干净，原始提交 `3cec0e2`。
- 原公开端 / 管理端两套 CSS、图标；Gallery / Wall 是同一个方形 warp 网格；
  全屏详情、无双主题、浏览器缩小“原图”等与目标不同。
- 原后端 Hono / SQLite / 文件存储，认证、相册、照片模块耦合旧 `/api`；
  没有服务器原图处理。旧数据不带可靠的原片档案。
- 原部署为 ten 的 `/home/ubuntu/fanphoto-dev` + `fanphoto-dev.service`，
  Caddy 的 `test.heabl.xyz` → `127.0.0.1:8787`。
- ten 没有 nginx，现有 Docker 服务都不是 FanPhoto，不可误删。
- 全部 26 个组件库、4 个图标库、3 个设计资源库和 54 份 skill 已阅读，
  清单与选型见 `ui-resources.md`。

## 新架构与选型（代码实施前）

```text
apps/client          React 19 + Vite + TypeScript
  gallery            平铺/环绕照片墙、筛选、背景详情
  studio             登录、照片库、上传、编辑、相册、设置
  ui                 Base UI + MingCute + 统一玻璃 / 主题 token
apps/server          Node 24 LTS + Hono
  core               配置、SQLite、存储、安全、错误响应
  modules            认证、媒体、图库、相册、设置
packages/contracts   Zod 请求契约与响应类型
scripts              开发、原图导入、构建、初始化、备份
deploy               systemd、Caddy 部署 / 清理工具
tests                新 API / 图像处理 / 布局 / 浏览器验收
```

- React Router：公开墙与可分享照片 URL；工作室独立懒加载。
- TanStack Query：分页和服务器状态。Motion：短暂转场；React Bits：Masonry、
  DomeGallery、GlassSurface 的可审计适配。Base UI 负责控件、键盘与焦点行为。
- 唯一图标体系 MingCute；系统字体、黑白灰 token；所有公开 / 管理 UI 使用同一套基础。
- Hono 为轻量 HTTP 层；照片业务服务独立于路由；SQLite WAL 足够单站使用，
  事务与索引明确；本地存储适配器可替换为对象存储。
- Sharp / exifr：服务器解码、方向校正、真实 EXIF、完整原文件档案、
  清洁多尺寸 WebP、ThumbHash、颜色 / 亮度分析。HEIC 使用成熟解码器兜底。
- 所有 API 仅在 `/api/v1`，无旧路由兼容。从第一版开始采用可扩展响应结构与
  命名空间模块钩子；数据表独立包含 assets、tags、albums、extensions 与 ingest 记录。
- 有界图片处理并发、请求 / 文件 / 像素限制、认证 / CSRF / 同源校验、
  私有原文件与公开派生图分离；公开媒体先验证可见性再进行条件缓存。
- 新空库、新管理员凭据；不导入旧测试库。只导入此次新下载并核验的风景原片。
- 发布与数据分离：`/home/ubuntu/fanphoto-next/{workspace,releases,current,data}`。
  本地与测试站运行同一代码和构建产物，区别仅环境变量。

## 实施顺序

1. 完成新架构骨架、契约、数据库 / 存储和媒体处理服务。
2. 实现全新认证、照片分页 / 搜索 / 详情、上传 / 导入、相册、管理与设置 API。
3. 展示页：自然比例平铺、无限环绕、悬浮模式 / 筛选 / 设置，
   明暗主题、左图右信息浮层、信息折叠和背景保留。
4. 全新管理页：登录、照片库、批量操作、回收站、原片上传队列、编辑、相册与设置；
   复用同一组件 / 图标语言，完整适配手机。
5. 补齐高质量真实风景素材的横 / 竖 / 方 / 全景比例，核验 EXIF、来源、作者、许可，
   每份原文件有 SHA256；不伪造缺失元数据。
6. 类型检查、API / 图像测试、桌面 / 手机浏览器全流程和截图验收，修复发现的问题。
7. 归档并清理旧测试站，部署新项目，导入风景图，在 `test.heabl.xyz` 复验完整流程。
8. 更新完整架构、开发 / 运维、备份 / 恢复、测试结果与来源说明。
