# 图片处理实现调研（ChronoFrame / Afilmory）与浏览器端适配

> 状态：调研完成。本文是 fanphoto 图片处理模块的设计底稿，
> 后续功能实现均参考这两个项目的实现细节（参数、算法、边界处理）。
>
> 代码位置（研究时 clone 于 `~/tmp/afilmory-research/`）：
> - ChronoFrame：`chronoframe/server/services/image/`、`chronoframe/server/services/video/`、`chronoframe/server/services/pipeline-queue/manager.ts`
> - Afilmory：`afilmory/packages/builder/src/image/`、`afilmory/packages/builder/src/photo/`

## 1. 两项目处理架构对比

| 维度 | ChronoFrame（运行时） | Afilmory（构建时） |
| --- | --- | --- |
| 处理时机 | 上传后**异步队列**（SQLite pipeline_queue，7 阶段状态机，3 workers 并发，重试 3 次） | **批量构建**（`build:manifest` 跑一遍存储全量照片），增量判断 |
| 产物 | 每张照片一行 DB 记录，前端 SSR 实时读取 | 静态 `photos-manifest.json`（v2）→ 前端清单驱动 |
| 增量 | 无（上传即处理） | `shouldProcessPhoto`：按 lastModified/强制标志/缩略图存在性跳过未变照片 |
| 缓存复用 | 无 | thumbHash/EXIF/影调分析均可复用现有 manifest 数据 |
| 图片库 | sharp（server 端） | sharp（server 端） |
| EXIF | exiftool-vendored（系统 exiftool 二进制） | exiftool-vendored（同） |
| HEIC 转码 | heic-convert | heic-convert |
| 通用 | HEIC/HEIF/HIF/TIFF/BMP/JPEG/PNG/WebP/GIF + MOV/MP4 | 同 + AVIF |

## 2. 各功能实现明细（参数可直接抄）

### 2.1 HEIC/HEIF 转码
两项目同款：`heic-convert` → **JPEG，quality 0.95**（ChronoFrame 对 >10MB 文件降为 0.8）。
转码后存 JPEG 版本（key 替换扩展名）。转换属重量级操作，ChronoFrame 用慢速重试策略（30s 超时，memory/timeout 错误重试）。

### 2.2 BMP → JPEG
`@vingle/bmp-js` 解码 → raw 数据 → sharp 重编码 JPEG。检查 channels 必须为 3/4。

### 2.3 元数据读取（尺寸/方向）
- ChronoFrame 的 `getMetadataWithSharp` 有 **4 级 fallback**：sharp.metadata() → clone().rotate() → 重新 toBuffer 再 metadata → 强制 jpeg 重编码后解析 **JPEG SOF 头**（手写 marker 扫描）
- `limitInputPixels: false` 关闭像素限制（防大图失败）
- orientation 5/6/7/8 → 交换宽高

### 2.4 EXIF 提取（核心，字段清单两项目几乎一致）
exiftool-vendored 读完整 Tags → **白名单 pick** 出所需字段。公共字段组：

```
时间: DateTimeOriginal/Digitized, OffsetTime(Original/Digitized), tz, tzSource
相机: Make, Model, Software, Artist, Copyright, Orientation
曝光: ExposureTime, FNumber, ExposureProgram, ISO, ShutterSpeedValue, ApertureValue,
      BrightnessValue, ExposureCompensation, MaxApertureValue, MeteringMode, LightSource, Flash
焦距: FocalLength, FocalLengthIn35mmFormat, ScaleFactor35efl
镜头: LensMake, LensModel
色彩: ColorSpace, WhiteBalance, WBShiftAB/GM, WhiteBalanceBias, WhiteBalanceFineTune
其他: ExposureMode, SceneCaptureType, SensingMethod, FocalPlaneX/YResolution, Rating
GPS:  GPSLatitude(Ref), GPSLongitude(Ref), GPSAltitude(Ref), GPSCoordinates(合成)
HDR: MPImageType, UniformResourceName, ContainerDirectory
Motion: MotionPhoto, MotionPhotoVersion, MotionPhotoPresentationTimestampUs,
        MicroVideo, MicroVideoVersion, MicroVideoOffset, MicroVideoPresentationTimestampUs
```

**Afilmory 独有**：
- **FujiRecipe**（FilmMode/GrainEffect/ColorChromeEffect/WhiteBalance/DynamicRange/HighlightTone/ShadowTone/Saturation/NoiseReduction/Clarity/ColorTemperature…，检测到 FilmMode 即聚合）
- **SonyRecipe**（CreativeStyle/PictureEffect/Hdr/SoftSkinEffect）
- **XMP keywords**（Subject/Keywords/WeightedFlatSubject/HierarchicalSubject 合并去重）
- **XMP regions**（人脸/主体区域：RegionInfo → name/type/area，供前端裁切建议）

**ChronoFrame 独有**：颜色空间推断（ICC 字符串匹配 sRGB/AdobeRGB/P3/ProPhoto + sharp space + 格式默认值，**HEIC 默认 Display P3**）。

### 2.5 拍摄时间与标题/标签提取
- 时间：EXIF DateTimeOriginal 优先 → 文件名 `YYYY-MM-DD` 正则兜底
- 标题：EXIF Title/XPTitle/Description → 文件名清洗（去日期前缀 `\d{4}-\d{2}-\d{2}[_-]?`、去 `\d+views` 后缀、`[_-]+` 转空格）
- 标签：Afilmory 额外支持**目录路径分段作为标签** + 文件名 `views` 计数解析

### 2.6 缩略图 + BlurHash
| 项 | ChronoFrame | Afilmory |
| --- | --- | --- |
| 尺寸 | **600px 宽**（withoutEnlargement, fastShrinkOnLoad:false） | **600px 宽**（withoutEnlargement） |
| 格式 | **WebP q85（>5MB 用 q85，否则 q100）** | **JPEG q100** |
| 方向 | sharp.rotate() 自动校正 | 同 |
| blurhash | thumbhash `rgbaToThumbHash`，对缩略图再 `resize(100,100,'inside')` → raw RGBA | 同（复用缩略图 Sharp 实例） |

### 2.7 直方图 + 影调分析
- ChronoFrame：**全像素**遍历 → RGB + 灰度（BT.709 **0.299/0.587/0.114**）各 256 bins → 归一化百分比
- Afilmory：先 `toColourspace('srgb')` + **`resize(256,256,'inside')` 降采样**（省内存，结果近似）→ RGB + luminance（BT.709 **0.2126/0.7152/0.0722**，与前端图表同口径）
- **影调分析（Afilmory 独有）**：
  - brightness = luminance 加权均值 /255×100
  - contrast = 标准差 /127.5×100
  - shadowRatio = bins[0..85] 之和；highlightRatio = bins[170..255] 之和
  - 分类：low-key（亮度<30 且 shadow>0.6）/ high-key（亮度>70 且 highlight>0.6）/ high-contrast（contrast>60 且两端>0.3）/ normal

### 2.8 GPS 与反向地理编码
- 解析：exiftool `GPSCoordinates` 合成字段
- 提供者：Mapbox（`api.mapbox.com`，language 参数，zh-Hans 映射）或 Nominatim（`accept-language` 头）
- **两者都有全局 rate limiter**（Nominatim 1 req/s 合规）；失败指数退避重试
- ChronoFrame：设置项可"上传自动抹除 GPS"（privacy.upload.autoEraseLocation）；Afilmory 版本粗化坐标（coarse 模式）

### 2.9 Live Photo（独立 MOV）
两项目同思路：**同名 basename 配对**（支持 HEIC/heic/JPG/jpg 大小写）。
- ChronoFrame：`isLivePhotoVideo` = 扩展名 .mov 且 **≤12MB**；扫描存储配对；不匹配不报错
- Afilmory：构建前先建 `livePhotoMap`（photos 列表 + videos 列表按 basename 匹配），处理时查表

### 2.10 Motion Photo（嵌入视频）
两项目均为：**从原始文件提取嵌入的 MP4 片段**。

| 步骤 | ChronoFrame | Afilmory |
| --- | --- | --- |
| 标志 | EXIF MotionPhoto/MicroVideo + **XMP 段扫描**（512KB 内 `<x:xmpmeta`，多命名空间正则） | 同标志，但标准走 **ContainerDirectory**（MotionPhoto item 的 Length → offset = 文件长 - Length） |
| offset 候选 | MicroVideoOffset + XMP 多源，**从文件头/文件尾两个方向**尝试 | ContainerDirectory 优先，legacy MicroVideoOffset 双向候选 |
| 校验 | `ftyp` 头（前 32 字节窗口），**尾部 8MB 内扫描 ftyp 兜底** | 同 ftyp 校验，无兜底扫描 |
| 产出 | 视频片段存 `{photoId}.mp4` | manifest 记 offset/size/presentationTimestamp（不切文件，**前端运行时按 offset 播放**） |
| 冲突 | — | **Motion Photo 与 Live Photo 互斥**，同时检测到直接报错 |

> 设计要点：Motion Photo 检测必须用**转码前的原始字节**（转码后 XMP/offset 会丢）。

### 2.11 HDR / GainMap（Afilmory 独有）
`detectGainMap`：EXIF `ContainerDirectory` 中找 `Semantic === 'GainMap'` 且有 Length。
`isHDR` 判定：`MPImageType === 'Gain Map Image'` 或 `UniformResourceName === 'urn:iso:std:iso:ts:21496:-1'` 或 gainmap 检测命中。

### 2.12 OG 图
- ChronoFrame：nuxt-og-image（运行时 satori 渲染）
- Afilmory：og-image 插件，构建时生成，URL 入 manifest（`ogImageUrl`），支持远程存储 vendors

### 2.13 photoId 与内容寻址（Afilmory）
`photoId = basename + '_' + sha256(s3Key).slice(0, digestSuffixLength)`；内容 `digest = sha256(图片字节)`。
清单项存 `lastModified/size` 用于增量判断。

## 3. 浏览器端适配评估（fanphoto CF 方案）

| 功能 | 浏览器端可行性 | 具体方案 | 与服务器版的差距 |
| --- | --- | --- | --- |
| HEIC 转码 | ✅ | **heic2any**（wasm libheif，与 heic-convert 同源技术） | 无差距；注意内存（单张串行） |
| EXIF 提取 | ✅ | **exifr**（已选型） | 主要字段全支持；**Fuji/Sony recipe、XMP regions、ContainerDirectory 深层字段弱**（exifr 不产 exiftool 级 Tags） |
| 缩略图 | ✅ | `createImageBitmap` 解码 → OffscreenCanvas → `toBlob('image/webp',0.8)` | 无差距 |
| blurhash | ✅ | thumbhash 库浏览器版（canvas 出 RGBA → `rgbaToThumbHash`） | 无差距 |
| 直方图/影调 | ✅ | canvas `getImageData` 遍历（或按 Afilmory 先降采样 256px 省时） | 无差距（浏览器内存够，可直接全像素） |
| BMP/TIFF | ⚠️ | BMP 可 bmp-js 浏览器版；TIFF 显示需 tiff.js 转换 | 边缘格式，v1 可降级不支持 |
| AVIF 输出 | ✗ | 浏览器编码 AVIF 不成熟 | 统一 WebP 输出即可（显示兼容性更好） |
| Live Photo MOV | ✅ | 上传时**同批选择 MOV**，浏览器端按 basename 配对后一并上传 | 反而更简单（客户端知情，无需扫描存储） |
| Motion Photo 提取 | ⚠️ | **转码前**用原始 ArrayBuffer 扫 ContainerDirectory/MicroVideoOffset → slice 出 MP4 上传 | 可完整实现；XMP 扫描逻辑是纯字符串正则，浏览器可抄 |
| HDR GainMap | ⚠️ | exifr 能读 MPImageType/UniformResourceName（浅标记）；gainmap 容器提取难 | v1 仅标记 isHDR，深挖放 v2 |
| 颜色空间推断 | ✅ | 抄 ChronoFrame 的 ICC 字符串匹配 + 格式默认 | 无差距 |
| GPS 反地理编码 | ✅ | 浏览器 fetch Nominatim（CORS 支持） | 注意限速 1 req/s；也可延迟到 v2 |
| OG 图 | ✅ | satori wasm（前端生成 PNG）或手传封面 | 实现成本略高，可 v2 |
| 增量/缓存 | — | 浏览器端每次全量处理，无需增量 | clientId 幂等代替 |

**结论**：图片处理主体（转码/EXIF/缩略图/blurhash/直方图/影调/LivePhoto）**全部可在浏览器端实现且无实质能力损失**；损失集中在"exiftool 级深层 EXIF"（recipe/XMP regions）和 HDR gainmap 深处理。这两项如需支持，备选方案是在管理端 Web Worker 里跑 **exiftool.wasm**（社区有移植），v2 再议。

## 4. fanphoto 图片处理管线设计（v1 定稿）

```
选文件（多选，MOV 可与照片同批选择配对）
  │
  ├─ 1. 转码前检测（用原始 ArrayBuffer）：
  │     exifr.parse → 时间/相机/GPS/MPImageType/MotionPhoto 标志
  │     Motion Photo：ContainerDirectory/MicroVideoOffset → 切 MP4（若有）
  │
  ├─ 2. 解码 + 转码：
  │     HEIC → heic2any → WebP(q0.85)
  │     其他 → createImageBitmap → canvas
  │
  ├─ 3. 派生产物（同一 canvas 原图，串行缩放）：
  │     original.webp(≤2048px) / lg(1600) / md(800) / sm(400)
  │     thumbhash（sm 图 resize 100×100）→ base64
  │     直方图 + 影调分析（md 图降采样 256px）→ JSON（v2 可选）
  │
  ├─ 4. 组装：meta(EXIF 白名单字段 + GPS + 配对视频) + 4 文件 → POST /api/photos/upload
  │
  └─ 队列 UI：逐张串行（内存）、进度条、失败单张重试（clientId 幂等）
```

**优先级**：

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| v1 必做 | HEIC→WebP、EXIF 核心字段（§2.4 公共组）、4 档缩略图、thumbhash、日期/GPS、LivePhoto MOV 配对上传、删除/编辑 | 最小闭环 |
| v2 可选 | 直方图/影调分析、Motion Photo 提取、反向地理编码、OG 图、exiftool.wasm 补全 recipe | 锦上添花 |
| 明确不做 | XMP regions 人脸框、HDR gainmap 深挖、AVIF 编码输出、BMP/TIFF 源显示 | 单人场景收益低 |

**存储预算更新**：4 档 WebP（original 0.8MB + lg 0.6 + md 0.2 + sm 0.05 ≈ 1.7MB/张 × 1000 = **1.7GB**，R2 免费 10GB 内）。
若不做 lg 档可省 0.6GB，查看器用 original 直出（首屏稍慢），由实现时取舍。
