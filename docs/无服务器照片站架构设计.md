# 无服务器照片站架构设计（Cloudflare 全家桶）

> 状态：设计定稿（v1 范围），待实现。
> 关联：本设计取代 README「暂定技术方向」中"服务端 ExifTool 解析"的旧方向，
> 改走 **浏览器端处理 + Cloudflare 无服务器** 路线。既有调研（EXIF 选型、ChronoFrame、
> Afilmory、no-gl-grid）作为参考保留。

## 1. 需求与约束

| 项 | 需求 |
| --- | --- |
| 使用者 | 单人（一个管理员，可匿名浏览） |
| 照片规模 | ~1000 张，格式混合（JPEG/PNG/WebP/HEIC/HEIF/TIFF） |
| 托管 | 无服务器、无常驻进程：Cloudflare Pages/Workers + R2 + D1 |
| 更新方式 | 动态：上传/删除/编辑后立即生效，不重新构建 |
| 管理功能 | 上传、删除、编辑标题/描述、站点设置、登录 |
| 免费额度 | 长期运行不付费（R2 10GB 存储、Workers 10万请求/天、D1 5GB） |
| 域名 | 需要自有域名（可挂现有 `heabl.xyz` 子域，如 `photos.heabl.xyz`） |

核心设计原则：**托管形态是静态/CDN，数据是活的**。页面永远在线，数据变更走
Serverless 函数 + 对象存储 + Serverless 数据库，不依赖任何"服务器"。

## 2. 总体架构

```
┌─────────────────────────── 浏览器（单一 React SPA） ───────────────────────────┐
│  访客视图: 瀑布流 / 详情(EXIF) / (v2 地图)        管理视图: /admin 登录·上传·删除·编辑│
│  ├─ exifr：读 EXIF/GPS        ┌─ heic2any：HEIC→WebP（浏览器端转码）            │
│  └─ Canvas：生成 3 档缩略图   └─ fetch：调 Worker API                            │
└───────────────┬───────────────────────────────────────────────┬───────────────┘
                │ 静态资源(HTML/JS/CSS)                           │ JSON API
┌───────────────▼───────────────┐              ┌──────────────────▼───────────────┐
│  Cloudflare Pages (静态)       │              │  Pages Functions (Hono Worker)   │
│  apps/web/dist  CDN 全球分发   │              │  /api/* 全部动态接口              │
│  /photos/* SPA fallback        │              │  认证(JWT)·上传·查询·管理         │
└───────────────────────────────┘              └───────┬──────────────┬──────────┘
                                                       │ R2 Binding   │ D1 Binding
                                              ┌────────▼───────┐ ┌────▼─────────┐
                                              │ R2 对象存储     │ │ D1 (SQLite)  │
                                              │ 原图+3档缩略图  │ │ 照片/站点元数据│
                                              │ 10GB 免费/出站0费│ │ 5GB 免费      │
                                              └────────────────┘ └──────────────┘
```

**组件职责**：

| 组件 | 职责 | 备注 |
| --- | --- | --- |
| React SPA | 浏览 + 管理两套视图；所有图片处理在浏览器完成 | 静态产物 `apps/web/dist` |
| Pages | 托管静态产物、CDN、`/photos/*` SPA fallback | 连接 GitHub 仓库自动部署 |
| Pages Functions | 全部动态 API；**不处理图片字节**，只做校验/签名/写库 | Hono，单个 `functions/` 目录 |
| R2 | 原图 + 缩略图（按 `{photoId}/original.webp`、`sm/md/lg.webp` 布局） | 图片 URL 走 R2 自定义域，CDN 缓存 |
| D1 | `photos`、`settings` 两张表；列表/详情/搜索由 SQL 完成 | 单人单表量级，无性能压力 |

**关键决策：图片处理放在浏览器端**（本设计最重要的取舍）：

| 方案 | 结论 |
| --- | --- |
| Serverless 函数处理大图 | ✗ Workers 内存 128MB、免费计划请求体 100MB，HEIC 解码/大图转码易 OOM 或超时 |
| 浏览器端处理 | ✓ exifr（纯 JS EXIF/GPS）、heic2any（HEIC→WebP）、Canvas（缩略图），成熟稳定；函数只写库 |

| 层 | 选型 | 理由 |

| 数据库 | D1 + Drizzle ORM（可选，v1 可纯 SQL） | SQLite 语义，类型安全 |

## 4. 数据模型（D1）

v1 只建 **2 张表**，从简。后续扩展见 §11。

```sql
-- 照片
CREATE TABLE photos (
  id            TEXT PRIMARY KEY,              -- nanoid(12)，同时作为 R2 目录名
  title         TEXT DEFAULT '',
  description   TEXT DEFAULT '',
  width         INTEGER,                        -- 转码后尺寸
  height        INTEGER,
  date_taken    TEXT,                           -- ISO 8601，EXIF 拍摄时间（转码后）
  original_mime TEXT,                           -- 落库文件类型（始终 webp/jpeg）
  original_size INTEGER,                        -- 字节
  exif          TEXT,                           -- JSON: camera/lens/iso/focal/aperture/shutter
  latitude      REAL,                           -- GPS（可空；设置可抹除）
  longitude     REAL,
  blur_hash     TEXT,                           -- v1 可选，渐进加载占位
  created_at    INTEGER NOT NULL                -- 入库时间戳(ms)
);
CREATE INDEX idx_photos_date ON photos(date_taken DESC);
CREATE INDEX idx_photos_created ON photos(created_at DESC);

-- 站点设置（单行）
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL                           -- JSON
);
-- 行示例: ('site', '{"title":"我的相册","slogan":"...","avatar":""}')
```

**R2 对象布局**（前缀分区，详见《存储与数据设计》：

```
originals/{id}.webp     ← 转码后原图（≤2048px）
thumbs/{id}/sm.webp     ← 瀑布流卡片 400px
thumbs/{id}/md.webp     ← 列表/详情 800px
thumbs/{id}/lg.webp     ← 查看器 1600px
videos/{id}.mp4         ← LivePhoto/Motion 视频（v2）
```

图片经 R2 自定义域（cdn 子域）直连，不消耗函数配额；
D1 每日导出备份写回同一 bucket `backup/` 前缀。

> 存储预算：1000 张 × (original 0.8MB + lg 0.6MB + md 0.2MB + sm 0.05MB) ≈ **1.7GB**，
> 远低于 R2 免费 10GB。缩略图统一 WebP（q80）。

## 5. API 设计

前缀 `/api`，全部 JSON。认证：除标注"公开"外均需 JWT（HttpOnly Cookie）。

| 方法 | 路径 | 认证 | 说明 |
| --- | --- | --- | --- |
| POST | /api/auth/login | - | `{password}` → 校验 ADMIN_PASSWORD，签发 JWT（7 天） |
| POST | /api/auth/logout | 管理 | 清除 Cookie |
| GET | /api/auth/me | 管理 | `{ok:true}` 探活 |
| POST | /api/photos/upload | 管理 | 批量上传，`multipart/form-data`（详见 §6） |
| GET | /api/photos | 公开 | 分页列表 `?cursor=&limit=50&sort=date_desc` → `{photos[], nextCursor}` |
| GET | /api/photos/:id | 公开 | 详情（含 exif 解析后的字段、R2 各档 URL） |
| PATCH | /api/photos/:id | 管理 | `{title?, description?, eraseLocation?}` 编辑/抹除 GPS |
| DELETE | /api/photos/:id | 管理 | 删 D1 行 + R2 目录（先列后删） |
| GET | /api/site | 公开 | 站点配置（标题/口号/作者） |
| PATCH | /api/settings | 管理 | 更新站点配置 |

**响应约定**：成功 `2xx`；错误统一 `{error: {code, message}}`。
**分页**：游标分页（`created_at`/`date_taken` 复合游标），避免深偏移。

**照片 URL 约定**（响应中直接给出，前端不拼路径）：
`https://cdn域/photos/{id}/{size}.webp`，R2 自定义域直连，天然 CDN 缓存（ETag/年龄头）。

## 6. 上传管线（核心流程）

### 6.1 时序

```
管理端 SPA                        Worker (Pages Functions)              R2          D1
  │ 选图 × N
  ├─ 逐张预处理（浏览器内）:
  │   exifr → 拍摄时间/相机/GPS
  │   HEIC/TIFF → webp (heic2any)
  │   Canvas → sm/md/lg 三档缩略图
  ├─ POST /api/photos/upload ──────────►│
  │  multipart: {meta:{title,clientId,dateTaken,exif,gps…}, files:{original,sm,md,lg}}
  │                              校验 JWT、魔数(file-type)、大小≤50MB/张
  │                              ├─ R2.put(photos/{id}/…) ─────────────►│
  │                              ├─ D1 INSERT ──────────────────────────►│
  │ ◄── 201 [{id, url…}]        │（失败回滚: 删已写对象）
```

### 6.2 浏览器端预处理步骤（每张图）

1. **读 EXIF**：`exifr.parse(file, {gps:true, tiff:true, exif:true})`
   → `dateTaken`、`camera/lens/iso/focal/aperture/shutter`、`lat/lng`。
2. **转码**：HEIC/HEIF/TIFF → WebP（`heic2any({format:'WEBP', quality:0.85})`）；
   JPEG/PNG/WebP 直接进 Canvas 统一走 WebP 输出（顺便剥除多余 EXIF、压缩体积）。
3. **缩放**：Canvas 依次生成 lg(1600) / md(800) / sm(400)，`toBlob('image/webp', 0.8)`。
4. **幂等键**：`clientId = crypto.randomUUID()`，Worker 按 clientId 去重（重试安全）。

### 6.3 Worker 端校验（不信任浏览器）

- 认证中间件（JWT）
- `file-type` 魔数校验每个文件（忽略 content-type）
- 单文件 ≤ 50MB、每批 ≤ 20 张
- clientId 唯一性（D1 查重，重复则幂等返回）
- 全部 R2 写入成功后 INSERT；任一失败 → 删除已写对象并返回 500

## 7. 前端设计

### 7.1 路由

| 路径 | 视图 | 说明 |
| --- | --- | --- |
| `/` | 瀑布流首页 | 网格卡片（sm/md 图 + 懒加载） |
| `/photos/:id` | 详情 | lg 图 + EXIF 面板 + 前后翻页 |
| `/admin/login` | 登录 | 单密码 |
| `/admin` | 上传 + 最近照片管理 | 拖拽多选、逐张进度条、成功列表 |
| `/admin/photos` | 管理列表 | 缩略图网格，批量删除/编辑 |
| `/admin/settings` | 站点设置 | 标题/口号/作者/抹除 GPS 开关 |

### 7.2 展示层复用既有成果

- 瀑布流/平滑交互参考 `demo/no-gl-grid` 的零依赖实现经验（matrix3d、视口缩放），
  v1 不必引入 WebGL 库，`<img>` + CSS 即可达到良好体验。
- 渐进加载：sm 图占位 + md 图渐进（blur_hash 可选 v1 后加）。

### 7.3 状态

- Jotai：`authAtom`（登录态）、`uploadQueueAtom`（队列 + 进度）、`siteAtom`（站点配置）。
- TanStack Query：照片列表/详情/管理列表的缓存与失效。

## 8. 认证与安全

| 项 | 方案 |
| --- | --- |
| 登录 | `ADMIN_PASSWORD` 环境变量（≥12 位）；登录签发 HS256 JWT（`SESSION_SECRET` 独立密钥） |
| Cookie | HttpOnly + Secure + SameSite=Lax，7 天过期 |
| CORS | 只允许本站域（同一 Pages 域名下同源，无需 CORS 配置；R2 自定义域图片请求为 `<img>` 不受 CORS 限制） |
| 上传安全 | MIME 白名单 + 魔数校验 + 大小限制 + 限流（按 IP 5 次/分钟的登录接口限速） |
| 隐私 | 站点设置提供"抹除所有 GPS"批量操作；上传默认保留 GPS（单人自用） |
| 密钥 | `SESSION_SECRET`、`ADMIN_PASSWORD` 用 `wrangler secret put`（不写入仓库） |

## 9. 部署与运维

### 9.1 目录结构（规划）

```
photo-site/
├── apps/web/                 # React SPA（Vite）
│   ├── src/
│   │   ├── pages/            # 见 §7.1
│   │   ├── components/       # GalleryGrid/PhotoViewer/Uploader/ExifPanel…
│   │   ├── lib/              # api.ts / exif.ts / heic.ts / thumbnails.ts / auth.ts
│   │   └── stores/
│   ├── functions/            # Pages Functions（Hono Worker 放这里，同域同项目）
│   │   ├── api/auth.ts / photos.ts / site.ts
│   │   ├── db/schema.ts + migrations/
│   │   └── _middleware.ts    # JWT 校验中间件
│   └── wrangler.jsonc        # D1/R2 binding、pages_build_output_dir、vars
├── docs/
└── package.json              # 根 workspace（web + functions 共享类型）
```

### 9.2 Cloudflare 资源创建

1. 账号 → R2 Bucket `photos`（创建自定义域 `cdn.photos.heabl.xyz` 或直接同域路径）
2. D1 数据库 `photo-site`，`wrangler d1 migrations apply`
3. Pages 项目连接 GitHub 仓库：构建命令 `pnpm build`，输出 `apps/web/dist`
4. `wrangler secret put` 设置 `ADMIN_PASSWORD`、`SESSION_SECRET`
5. 自定义域 `photos.heabl.xyz` 绑定 Pages 项目（自动 HTTPS）

### 9.3 环境变量

| 变量 | 用途 | 来源 |
| --- | --- | --- |
| ADMIN_PASSWORD | 登录密码 | secret |
| SESSION_SECRET | JWT 签名密钥（≥32 字符随机） | secret |
| D1 binding `DB` | 数据库 | wrangler.jsonc |
| R2 binding `PHOTOS` | 对象存储 | wrangler.jsonc |

### 9.4 CI

GitHub Actions（可选）：push 到 main → `pnpm install && pnpm build` + 类型检查；
Pages 侧由 Cloudflare 自动拉取构建（或 actions/deploy-pages 显式推送产物）。

## 11. Roadmap

**v1（本设计范围）**：登录 → 上传（浏览器端处理）→ 瀑布流浏览 → 详情 EXIF → 删除/编辑 → 站点设置。

**v2 扩展**（表结构/接口草案，不在 v1 实现）：

```sql
CREATE TABLE albums (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, cover_photo_id TEXT, created_at INTEGER
);
CREATE TABLE album_photos (album_id TEXT, photo_id TEXT, position INTEGER, PRIMARY KEY(album_id, photo_id));
-- photos 表增加 tags TEXT  (JSON string[])
```

- 相册/标签：`GET /api/albums`、`POST /api/albums`、`PUT /api/photos/:id`（tags 字段）
- 地图：photos 有 GPS 的行 → `GET /api/photos/map`（轻量点位 JSON），前端 MapLibre 聚类
- 反向地理编码：管理端可选调用 Nominatim（单人手动触发，限速 1 req/s）
- 搜索：D1 `LIKE` 标题/描述/标签（千行级足够，不必全文索引）
- 分享：单张公开链接页（v1 已有 `/photos/:id`，无需额外工作）
- 批量导入（历史存量）：v1 上传一次一张；v2 提供压缩包批量解压或目录拖拽

**明确不做**：多用户/权限系统、评论点赞社交、视频、定时任务、Webhook。

## 13. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 浏览器处理受设备性能影响（老手机 HEIC 转码慢） | 转码前降级：HEIC→JPEG(q85) 而非 WebP；显示逐张进度；失败可重试单张 |
| 100MB 请求体上限（Workers 免费计划） | 单批 ≤20 张且单张 ≤50MB；超限时拆批 |
| R2 自定义域缓存陈旧（改图后旧图仍在 CDN） | 对象 key 含不可变 ID（photoId），**编辑只改 D1 不改图**，新上传即新 key，天然规避 |
| 误删 | DELETE 二次确认；v2 加"回收站"（软删除字段 `deleted_at`） |
| 忘记 ADMIN_PASSWORD | 环境变量改值即改密码（登录后原 Cookie 失效由签发校验时间戳保证可选） |
